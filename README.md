# 精确分页排版台（Imposition Bench）

面向印前安全操作卡场景的**纯前端**排版台：导入一批带高度的内容块与页容量，
人工逐项标记「强制分页 / 与后项同页」边界后，计算**严格满足所有边界**且
**最小化 Σ 每页剩余高度²** 的精确分页方案。支持正反面可印高度不同的
**双面纸张**（可选 `backPageHeight`）：第 1 页为正面、此后正反交替，
各页按自身实际容量约束与计代价。双面文档还可按块声明 **`startOnFront`**
（章节必须从纸张正面起始）：必要时算法自动在该章节前留一张**空白背面
过渡页**（按背面完整剩余容量计入代价），而不是先排完再事后补页。

- TypeScript + React 18 负责交互，Vite 构建
- 无后端、无任何网络调用；导入、计算、下载全部在浏览器本机完成
- Vitest：小规模**穷举**（单容量约 14 万组 + 双面约 8 万组 + startOnFront 全标记
  子集输入，分别与朴素 O(n²) DP / 独立 O(n²) 页数奇偶 DP / 独立枚举对拍）
  + 20 万块**大夹具**验收
- 200,000 块规模实测约 **90–350 ms**（要求 ≤ 4 s），单双面算法均为均摊 O(n)

## 数据约定（导入 JSON）

顶层为一个普通 JSON 对象，UTF-8 编码：

```json
{
  "pageHeight": 300,
  "blocks": [
    { "id": "title",         "height": 60 },
    { "id": "warn-hot",      "height": 90, "sameAfter": true },
    { "id": "warn-hot-body", "height": 80 },
    { "id": "step-2",        "height": 150, "breakAfter": true },
    { "id": "warn-chem",     "height": 70, "sameAfter": true },
    { "id": "warn-chem-body","height": 110 }
  ]
}
```

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `pageHeight` | 整数 | 1 ≤ pageHeight ≤ 10000（双面模式下为**正面**容量） |
| `backPageHeight` | 整数，可省略 | 1 ≤ backPageHeight ≤ 10000；存在即启用**双面模式** |
| `blocks` | 数组 | 1 ≤ 长度 ≤ 200000，顺序即排版顺序 |
| `blocks[].id` | 字符串或安全整数 | 在数组内**唯一**（数字 `1` 与字符串 `"1"` 视为不同 id）。数值 id 必须是 Number 安全整数（`−9007199254740991..9007199254740991`，无小数）；`Infinity`/`NaN`/超出安全整数范围的数值会被拒绝——它们无法经 JSON 无损往返（`Infinity` 序列化为 `null`，超大整数被舍入）。超大标识请使用字符串 id |
| `blocks[].height` | 整数 | 1 ≤ height ≤ 页容量（双面模式下 ≤ max(pageHeight, backPageHeight)） |
| `blocks[].breakAfter` | 布尔，可省略 | 该块与后一块之间**强制分页** |
| `blocks[].sameAfter` | 布尔，可省略 | 该块与后一块**必须同页** |
| `blocks[].startOnFront` | 布尔，可省略 | **仅双面**：该块必须成为某个**正面页的首块**；全文档最多 2000 处。单面文档声明该标记（`true`）即被拒绝 |

双面模式（`backPageHeight` 存在时）：

- 第 1 页为**正面**（容量 `pageHeight`），此后正反交替（背面容量 `backPageHeight`）；
- 每页保持连续且非空，按**各页实际容量**约束并计算剩余高度平方和；
- 同页链只需放进某一侧：链高不超过两侧较大容量时，算法自动把它约束到
  装得下的一侧（奇偶位置无可行安排时判无解）；
- `startOnFront` 标记块必须成为正面页首块。为满足面别，**只有背面**允许作为
  转正面的**空白过渡页**：空白页不含任何块（空区间）、恒为背面、按背面完整
  剩余容量 `backPageHeight²` 计入代价，并显式出现在结果与导出中（块区间序列
  仍连续不重不漏）。该约束与 `breakAfter`/`sameAfter`/正反不同容量一起进入
  同一全局最小二乘 DP，而不是先算完旧方案再补空白页；
- 同页链跨越强制正面起点（标记块前一边界为「同页」），或从标记块出发的
  同页链总高超过正面容量时，判无解并**定位到冲突块**；
- 文档无 `startOnFront` 标记时，结果与算分和引入该特性前逐项一致（不出现空白页）；
- 省略 `backPageHeight` 时，解析、计算、页面与导出结构与单容量版本逐项一致。

边界语义（边界 i = 第 i 块与第 i+1 块之间）：

- 无标记：算法自由决定是否在此分页；
- `breakAfter: true`：边界两侧**不得**同页；
- `sameAfter: true`：边界两侧**必须**同页（用于防止警示标题与正文被人工拆页）；
- 两者同置即为**冲突**。最后一块上的两个标记无意义，导入时忽略。
- `startOnFront: true` 是**块级**标记（不是边界标记），对最后一块同样有效；
  仅双面文档可用，全文档最多 2000 处，单面文档声明即被拒绝。
- 导入文件中出现的任何其他字段（包括本工具导出的 `pagination` 等）一律忽略，
  因此导出文件可以直接重新导入。

非法导入（结构、类型、范围、唯一性、标记类型等不满足约定）会被拒绝并提示原因，
**当前文档与已采纳版本保持不变**。

## 交互与计算规则

- 每个块后边界可在下拉框中逐项切换为：无标记 / 强制分页 / 与后项同页 / 两者同置。
- 双面文档每个块另有「正面」勾选（`startOnFront`）：该块必须从纸张正面起始；
  单面文档不提供此开关。
- 冲突（两者同置）出现时：顶部与列表立即标红、可点击定位，并**禁止计算**。
- 点击「运行精确分页」后四秒内显示：**页数、代价 Σ(剩余高度)²、覆盖范围**（及每页
  块号/id 区间、已用/剩余高度；双面模式额外展示每页的**面别与容量**，顶部同时
  显示正、背两种容量；**空白过渡页**以虚线卡片显式列出）。
- 边界被修改后，旧结果标记为「已过期」，需重新计算才能采纳/下载。
- 只有一次**成功且为最新**的计算结果可以「采纳」；采纳后可随时下载**与画面一致**
  的 JSON（边界标记 + 分页结果 + 代价）。
- 无解（例如同页链总高超过页容量、同页链跨越强制正面起点）或计算异常只显示原因
  与涉及块区间，**不采纳旧结果**；修正边界后可立即重新计算并得到最优分页。

### 导出 JSON 结构

```json
{
  "pageHeight": 300,
  "backPageHeight": 260,
  "blocks": [
    { "id": "title", "height": 60 },
    { "id": "warn-hot", "height": 90, "sameAfter": true }
  ],
  "pagination": {
    "pageCount": 2,
    "cost": 9800,
    "pages": [
      {
        "page": 1,
        "side": "front", "capacity": 300,
        "startBlock": 1, "endBlock": 4,
        "startId": "title", "endId": "warn-hot-body",
        "used": 230, "remaining": 70
      }
    ]
  },
  "adoptedAt": "2026-09-20T12:00:00.000Z"
}
```

`startBlock`/`endBlock` 为 1 起块号的**半开区间 `[startBlock, endBlock)`**：
`startBlock` 是本页首块块号，`endBlock` 是下一页首块块号（末页为 `块数 + 1`）。
因此单块页为 `[k+1, k+2)`（起、止不相等），相邻页满足
`pages[i].endBlock === pages[i+1].startBlock`；`endId` 指向本页末块
（即块号 `endBlock - 1`），数值与标识不再矛盾，外部系统按半开语义取块不重不漏。
首页 `startBlock` 恒为 1，末页 `endBlock` 恒为 `blocks.length + 1`。
`backPageHeight` 与每页的 `side`/`capacity` 仅双面文件写出；重新导入时
`backPageHeight` 会被读回以恢复双面计算语义（`pagination` 字段仍被忽略）。
单容量导出不包含这三个键，结构与引入双面模式前逐项一致。

**空白过渡页**（仅双面且存在 `startOnFront` 标记时可能出现）在导出中显式表达：
携带 `"blank": true` 与 `side: "back"`，`startBlock === endBlock`（空区间、
不消耗块），无 `startId`/`endId` 键，`used` 为 0、`remaining` 为背面容量；
相邻页区间链仍满足 `pages[i].endBlock === pages[i+1].startBlock`，覆盖不重不漏。
被标记块的 `startOnFront: true` 在 `blocks` 中原样写回，重新导入后语义完全恢复。

## 优化模型与算法

令前缀高度和 `S[i]` 为前 i 块之和，页面 `(j,i)`（半开区间）代价
`(H − S[i] + S[j])²`，动态规划：

```
dp[i] = min over 合法 j: dp[j] + (H − S[i] + S[j])²
```

展开后每个 j 是一条直线（斜率 `−2·S[j]` 随 j 严格递减，查询点 `S[i]` 严格递增），
用**凸包单调队列**把转移降到均摊 O(n)、空间 O(n)。

**双面模式**：页的面别由页数奇偶决定（第 1 页正面、交替），DP 状态携带奇偶：

```
dp[p][i] = min over 合法 j: dp[1−p][j] + (H_p − S[i] + S[j])²   (p ∈ {正, 背})
```

两个面别各维护一个凸包队列（斜率与面别无关、截距各含 `dp[1−p][j]` 与对应容量），
容量窗口指针各自单调，整体仍为均摊 O(n)、空间 O(n)——不按页数展开，
也不是「先按单一容量分页再校验」。

**startOnFront（仅双面）**：标记块 k 必须成为正面页首块，两条约束直接进入同一 DP：

- 任何页不得把 k 包在内部（页起点下界随最近标记块单调抬升，与强制分页下界同理），
  且 k 的候选线不进入背面凸包（背面页不得以标记块为首）；
- **空白背面过渡页**：正面内容页之后允许插一张空白背面（代价 `backPageHeight²`），
  使下一内容页仍为正面。于是正面页 `(j,i)` 的前驱代价取
  `min(dp[背][j], dp[正][j] + 背容量²)`——同一 j 的两条候选线斜率与容量项完全一致，
  仅截距不同，折叠为一条线进入正面凸包，均摊 O(n) 性质不变；回溯时若前驱为
  `dp[正][j]` 则补出一张空白背面页。文档无标记时两处均恒等退化，算分与结构不变。

实现要点（见 `src/core/paginate.ts` 注释）：

- 边界约束转化为页面**起点/终点可行性**：页内不得跨越强制分页；页首前边界、
  页尾边界不得是「同页」。「同页链总高 > 页容量」（双面取两侧较大值）在线性
  预检中直接判无解。
- **滑动窗口下的凸包删除是本实现的关键正确性点**：朴素做法会删除相对前后线
  全局冗余的中线，但当前线因容量/强制分页从队首过期后，被删的中线可能在
  可行集内重新最优。只有当「后线接管点 ≤ 前驱线的失效横坐标」时才允许删除
  （穷举对拍捕获到了这个反例：H=5、高度 [2,3,1]）。
- 交叉点比较全部使用 **BigInt**（`S[j]²` 可达 4×10¹⁸，Double 比较会出错），
  而代价数值本身仍在 Number 安全整数范围内（≤ 2×10¹³）。
- 多个方案达到同一最小代价均为合格，回溯得到其中一个确定方案。

## 验收覆盖

- **小规模穷举（单容量）**：n = 1..6、页容量 5/6/9、全部高度序列（单块高度 {1,2,3,5}）
  与全部边界赋值（n≤4 时含冲突的 4^(n−1) 全组合），逐例与朴素 O(n²) DP
  比较代价，并校验分页连续性、容量、全部边界约束与回算代价一致。
- **小规模穷举（双面）**：n = 1..5、正背容量组合 (5,3)/(3,5)/(4,2)/(5,5)、
  全部高度序列（单块高度可达两侧较大值）与全部无冲突边界赋值，逐例与独立
  O(n²) **页数奇偶 DP** 对拍，并校验面别交替、各页容量与回算代价。
- **小规模穷举（startOnFront）**：n = 1..5、同样四组正背容量、全部高度序列 ×
  全部边界赋值 × 全部标记子集（n≥4 按固定间隔抽样），逐例与**独立枚举**
  （递归枚举内容页切分与空白背面过渡）对拍最优值，并校验空白页恒为背面、
  区间连续不重不漏、每个标记块都是正面页首块、同价重算结果稳定。
- **锁定用例**：正面 5、背面 3、块高 [2,3,2,3] 返回三页且代价 5
  （而非单容量 5 下的两个满页、代价 0）；同页链只适配一侧时约束到对应面；
  标记块落背面奇偶位时恰好插入一张空白背面（代价含 `背容量²`）；
  同页链跨越强制正面起点 / 标记链超正面容量时判无解并定位到冲突块。
- **中等交叉验证**：5000 块随机文档（单容量、双面可行、双面块高可达较大侧、
  双面 + 随机 startOnFront 四种），与朴素 DP / 独立枚举代价与判定一致。
- **大夹具**：200,000 块单/双面随机种子、200,000 块双面 + 2000 处 startOnFront、
  200,000 块每页一块（单/双面各 20 万页、代价 0）、200,000 块同页链无解；
  原生运行 ≤ 4 s（实测单面约 0.1–0.2 s、双面约 0.2–0.4 s）。
- **结构不变性**：省略 `backPageHeight` 时解析、计算、页面与导出结构逐项不变
  （导出不含 `backPageHeight`/`side`/`capacity` 键）；双面导出固化
  `backPageHeight` 与每页 `side`/`capacity`，重新导入恢复双面语义；
  无 `startOnFront` 标记的双面文档不写出 `startOnFront`/`blank` 键；
  单面文档声明 `startOnFront` 即被拒绝。
